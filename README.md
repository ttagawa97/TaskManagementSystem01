# タスク管理システム

正式仕様は `specs/`、開発計画は `development_plan.md`、再開時の状況は `development_progress.yaml` を参照してください。

## 別のPCから再開する場合

このリポジトリのファイル一式を別PCへコピーまたは共有リポジトリから取得してください。最初に `development_progress.yaml` の `current_phase`、`gate`、`next_actions`、`pending_question`、`verification_results` を確認します。正式仕様は `specs/`、作業順序は `development_plan.md` が基準です。

`.env.development` はGit対象外のマシン固有の秘密情報です。別PCでは内容をコピーせず、`python3 execute/prepare-development.py` でそのPC用に新しく生成してください。開発DB・画像はDockerボリュームに保存されるため、通常のGit取得では引き継がれません。必要なデータがある段階では、別途バックアップと復元手順を決めてから移行します。P2以降に作成したユーザー・監査ログ・セッションはDockerボリューム内にあるため、別PCへデータを引き継ぐ場合はバックアップ方式の決定が必要です。

別PCのDocker EngineとComposeが利用できることを確認後、通常の起動手順を実行します。ポートはそのPCの `127.0.0.1:8000` を使用します。

## ローカル開発環境

このマシンのDocker EngineとComposeを使用します。DjangoとPostgreSQLを別コンテナで起動し、Google Chromeで `http://127.0.0.1:8000` を開きます。DBはホストへ公開しません。

```bash
python3 execute/prepare-development.py
bash execute/start-development.sh
bash execute/test-development.sh
```

再起動と永続化を確認する場合は `python3 execute/verify-development.py` を実行します。開発用コンテナを再起動し、検証用DBレコードとファイルの保持を確認してから検証データを除去します。

秘密値は初回のみ `.env.development` に生成されます。このファイルはGit対象外です。起動のたびに秘密値を作り直さないでください。

停止は次のコマンドです。DB・画像の永続ボリュームは保持されます。

```bash
bash execute/stop-development.sh
```

コード変更後は起動シェルを再実行すると再ビルドします。開発環境はDjango開発サーバーを使用し、本番公開の構成ではありません。

## P1の確認範囲

- ホームの基本配置と日本時間表示
- `/health/` でアプリとDBの接続確認
- 起動・停止・再起動後の永続化
- 開発コンテナ内の一時テストDBを用いた機能テスト

認証・ユーザー管理はP2で追加済みです。チケット等の業務画面は後続フェーズで追加します。

動作ログはコンテナごとに10MB×3ファイルでローテーションします。後続で実装する監査ログの無期限保持とは別です。ログを確認する場合は次のコマンドを使用します。

```bash
docker compose --env-file .env.development -f compose.development.yaml logs --tail=100
```

ボリューム削除を伴う操作は通常の起動・停止手順に含みません。バックアップ・復旧方針と本番構築は保留です。

依存関係は[Djangoのサポート表](https://www.djangoproject.com/download/)、[Python互換表](https://docs.djangoproject.com/en/5.2/faq/install/)、[PostgreSQLドライバー要件](https://docs.djangoproject.com/en/5.2/ref/databases/)を確認して選定しています。実際の固定版は `specs/05_infra_spec.yaml` とイメージ・依存定義を参照してください。

## P2：初期管理者と認証の確認

起動後、同じマシンの端末で次のコマンドを実行し、ID・表示名・初期パスワードを入力してください。パスワード入力は画面に表示されません。初期管理者の作成は初回のみです。

```bash
bash execute/create-initial-admin-development.sh
```

Google Chromeで `http://127.0.0.1:8000` を開き、作成したIDと初期パスワードでログインします。72時間以内にログイン・パスワード変更を完了してください。新パスワードは12文字以上で、現在と異なり、一般的すぎる文字列・IDに類似する文字列・数字だけの文字列を避けてください。

ユーザー管理からユーザー作成・編集・管理者権限の変更・パスワード初期化を行えます。発行された仮パスワードは直後のみ表示され、管理者がTeamsで本人へ手動連携します。期限は発行から72時間、期限切れ時は管理者が再発行します。初期化すると対象ユーザーの既存ログイン状態も無効になります。

ログイン状態はログイン時点から24時間固定です。操作・パスワード変更で延長しません。最後の有効なシステム管理者の権限解除は禁止しています。ユーザー無効化はチケット等の制約を実装するP4で追加します。

ログイン後のパスワード変更は、画面上部のユーザー名を選んで「プロフィール変更」を開きます。プロフィール変更画面内で現在のパスワードと新しいパスワードを入力してください。初回・初期化後の強制変更はログイン後に直接表示されます。

P2の画面レビューでは「初回ログインと変更 → ユーザー作成 → 別ユーザーでログインと変更 → 管理者による初期化」を確認してください。監査ログは各変更と同じトランザクションで記録されます。ログ閲覧画面はP6で追加します。

## P3：プロジェクト・参加者・マスター管理

ログイン後のダッシュボードに、参加中のプロジェクトと自分の担当チケットが表示されます。プロジェクト名を選ぶとそのプロジェクトのチケット一覧を開きます。システム管理者はプロジェクト一覧からプロジェクトを作成し、初期管理者を1名以上指定してください（複数選択可）。必須ステータス4件と初期種別4件が自動作成されます。

各行の「プロジェクト設定」から参加者追加・管理者権限変更・ステータス管理・種別管理へ移動できます。基本情報と管理者権限の変更はシステム管理者のみ、参加者追加とマスター管理はシステム管理者または当該プロジェクト管理者が行えます。システム管理者は未参加のプロジェクトでも操作可能です。一般参加者は参加中のプロジェクトだけを閲覧できます。

アーカイブすると管理操作を含む変更ができなくなります。変更前に解除してください。アーカイブ・解除は対象プロジェクトを表示する確認画面から実行します。必須ステータスは変更・無効化できず、最後の有効なプロジェクト管理者は解除できません。

画面レビューでは「プロジェクト作成 → 参加者追加 → 管理者指定・解除 → ステータス・種別の追加／名称変更／無効化／再有効化 → アーカイブと解除」を確認してください。参加者削除・担当解除はチケット機能と合わせてP4で追加します。

## P4第1区切り：チケットCRUD・検索

ログイン後はダッシュボードを表示します。参加プロジェクト、自分の担当チケット、現在担当・作成・過去担当のチケット更新ログを確認できます。プロジェクトを選ぶと、そのプロジェクトのチケット一覧・操作と設定へ移動します。プロジェクト内画面のナビからダッシュボードへ戻れます。プロジェクト一覧からチケット作成へ進み、タイトル・説明・ステータス・種別・優先度・担当者・日付を保存できます。チケット行を開くと既存値を編集でき、保存後は所属プロジェクトのチケット一覧へ戻ります。フォームの「キャンセル」も一覧へ戻ります。削除は作成者・当該プロジェクト管理者・システム管理者のみ確認画面を経て実行できます。監査記録は保持します。

チケット編集画面はパンくずを置かず、見出しにチケットタイトルだけを表示します。説明とコメントのMarkdownは「プレビュー」ボタンからポップアップで確認できます。編集画面では説明欄をコンパクトにし、コメント入力欄を履歴より上に表示します。「チケット検索」は参加中の複数プロジェクトを横断し、担当者に自分を指定して担当チケットを検索できます。専用の担当チケットメニューはありません。プロジェクト内一覧は選択したプロジェクトに固定されます。複数選択は同項目OR・別項目ANDです。検索条件はページ移動でも保持します。完了・アーカイブ済みも表示対象です。

中間レビューでは「ダッシュボード → プロジェクト選択 → チケット作成・編集 → 担当者を自分に設定してダッシュボードを確認 → 複数条件検索 → 削除確認」をお試しください。アーカイブ中は変更できません。無効化済みマスターは既存値の保持だけが可能です。

チケット編集画面の下部でMarkdownコメントを投稿できます。本文またはファイルを必須とし、投稿者の表示名とユーザーIDは投稿時点で保存します。添付はPDF・Office等を含む任意形式、1ファイル10 MiB以下・1コメント10個までです。添付は認可後のダウンロードとして配信します。

P4全体は進行中です。中間レビュー後に親子制約、その後に参加者削除・担当一括解除・ユーザー無効化を追加します。コメント・画像・WikiはP5、監査ログの全件閲覧はP6です。

Markdown依存の選定資料：[markdown-it-py](https://pypi.org/project/markdown-it-py/)、[描画時の安全対策](https://markdown-it-py.readthedocs.io/en/latest/security.html)、[nh3](https://pypi.org/project/nh3/)、[nh3 API](https://nh3.readthedocs.io/en/latest/)。固定版はapp/requirements.txtに記録しています。

全体設定は左メニューの「設定」からユーザー管理へ進みます（システム管理者のみ）。プロジェクト名を選ぶとチケット一覧を開きます。プロジェクト固有の基本情報・参加者・ステータス・種別・アーカイブ操作は、一覧の各行またはチケット一覧の「プロジェクト設定」から開きます。

チケット検索は折り畳み式のプルダウンで候補をチェックして複数選択します。閉じた状態では選択名と追加件数を表示し、検索欄は選択項目・キーワード・件数・検索操作を横一列にまとめています。候補は重ねて開き、Escまたは欄外クリックで閉じられます。
